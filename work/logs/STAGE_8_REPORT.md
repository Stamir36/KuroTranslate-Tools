# Этап 8 — полное покрытие .tbl японским текстом

Цель этапа (по замечанию): **все .tbl должны извлекать весь японский текст**, а не
отдавать hex. Приоритет — игровые файлы с текстом (`t_voice`, `t_status`, `t_npc_*`,
`t_place`, `t_lookpoint`, `t_help`, …); монотонные `t_evmes_*`/`t_chatmes_*` не важны.

## 1. Что было не так
1. **Метрика была неверной.** `diagnose_tbl_text.py` считал «сырые» строки регуляркой
   `[\x20-\xff]{2,}`, которая **рвёт длинные строки по `\n`** и потому завышала потери
   (например, `t_keyword`: «711 строк» — на деле 264; `t_event`: «844» — на деле 264+).
   Часть файлов числилась «потерянными»/«частичными» ложно.
2. **21 из 41** «потерянных» таблиц закрывались простым повторным прогоном вывода схем
   с `-g Kyoto` (в тот раз аргументы с `\r` из CRLF-файла срывались → статус `MISSING`).
3. Оставшиеся таблицы (`t_voice`, `t_npc_c*`, `t_place`, `t_chr_name`, `t_lookpoint`,
   `t_mapjump`, `t_action_*`) не выводились как схема из-за уникальной модели пула
   (повторяющиеся/пустые указатели, строки не в порядке записей) — байт-точную схему
   вывести не удавалось, и `tbl2json` откатывался на hex без текста.

## 2. Что сделано
### 2.1 Дозакрыты схемы (полный доступ к тексту + byte-exact)
Повторный вывод схем `tools/apply_inferred_schemas.py` (политика «оставлять только EXACT»)
по всем 41 потерянным и 3 частичным файлам. Впервые закрыты, с байт-точностью:
`t_action_card_support` 83, `t_chapter` 8, `t_dlc` 90, `t_ending_production` 32,
`t_help` 406, `t_monster_note` 245, `t_realtime_tutorial` 453, `t_sacred_tree` 70,
`t_shop_normal` 122, `t_skill` 45, `t_soul_ability_tree` 276, `t_spot_menu` 34,
`t_status` 299, `t_team_name` 450, `t_event` 844, `t_todo` 73, `t_keyword` 264
(+ ещё 7 EXACT-без-текста: `t_inc`, `t_npc_c0000/1/0300/0600`, `t_scptxt_a1004/c0020`).

### 2.2 Универсальный «текстовый пул» для таблиц без выводимой схемы
Когда схему вывести нельзя, `tbl2json.py` теперь **дополнительно** кладёт в JSON:
* `tail_start` — абсолютное смещение хвоста;
* `tail_strings` — массив `{offset, len, text}`: каждая NUL-terminated строка UTF-8 в
  хвосте с её смещением и длиной.

`json2tbl.py` при наличии `tail_strings` **собирает хвост заново**: сплайсит строки
по местам (правленый текст → новые байты), а в hex-записях **правит 8-выровненные
указатели** в хвост с учётом сдвига. Если текст не меняли — хвост и записи
восстанавливаются **байт-в-байт**.

Это даёт:
* **текст в JSON** для «трудных» таблиц (в т.ч. `t_voice` — 9001 строк-идентификаторов
  голоса, `t_npc_c*`, `t_place`, `t_chr_name`, `t_lookpoint`, `t_mapjump`, `t_action_*`);
* **возможность перевода**: правишь `text` в JSON → `json2tbl` → корректный .tbl
  с пересчитанными указателями.

Схема пула реализована так, что затрагивает **только** файлы, где `data_dump` пишется
последним и перекрывает область пула (т.е. hex-откат); 842 файла с рабочей схемой не
затронуты.

### 2.3 Корректная диагностика
`tools/diagnose_tbl_text2.py` — считает строки **правильно**: как NUL-terminated
валидный UTF-8 в хвосте. Именно её показатели — истина.

## 3. Результат
| Проверка | Было (до этапа) | Стало |
|---|---|---|
| `batch_tbl.py` (round-trip) | 842/844, 0 ошибок | **842/844, 0 ошибок** |
| Полностью потерянные .tbl | 26 | **0** |
| Частичные (реальные) | 3 | **0** (2 — артефакты скана, текст в JSON есть) |
| JP-строк в хвостах извлечено | 23539 | **27333 из 27359** |
| Без JP в JSON | много | **0** |

Остаток «26 не извлечённых» — **ложные срабатывания**: в хвосте строка лежит с
4-байтным двоичным префиксом (`2B 2F 2C 2F 合同演習を開始する`), сканер выдаёт
`+/,/合同演習…`, а в JSON та же строка есть **без** префикса. Проверено вручную
(`合同演習を開始する`, `刻印騎士`, `霊威狩り②` и др. — присутствуют в JSON).

Про `t_voice`: японского текста в нём **нет** вообще — это идентификаторы озвучки
(`v00_s0039`, `test_gaya_01`, …). Теперь они извлекаются как 9001 строк пула (раньше —
hex). Для перевода они не нужны (менять нельзя — сломается воспроизведение голоса).

## 4. Карта перевода
`tools/build_translation_map.py` переведён на `tail_strings`: для таблиц без схемы
строки берутся из текстового пула (kind=`tbl_tail`, редактируемые). Грубый скан всего
.tbl убран — он давал мусор из бинарных байт, ошибочно декодируемых как CJK.
Итог: `scripts.jsonl` 46606, `tables.jsonl` **33900**, `MAP_INDEX.csv` 1860 строк
(1603 ok / 257 empty). Каждый .tbl, содержащий японский текст, имеет его в JSON.
