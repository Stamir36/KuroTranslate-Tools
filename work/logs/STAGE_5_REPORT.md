# ЭТАП 5 — Таблицы (.tbl): схемы + reversible json→tbl round-trip

**Статус: ЗАВЕРШЁН (99.8% byte-exact).** Два файла — BLOCKED (нужны собственные Kyoto-схемы).

## 1. Цель этапа
Для каждой `.tbl` из `work/extract/table/` (844 шт.):
1. разобрать в JSON (`tbl2json.py` со схемами `KuroTools/schemas/`),
2. собрать обратно (`json2tbl.py`),
3. сравнить с оригиналом байт-в-байт (`work/tools/batch_tbl.py`).

Метрика этапа = доля таблиц, проходящих round-trip **byte-exact**.

## 3. Корневые причины исходных 84 сбоев (и что исправлено)

Ключевой вывод: **проблема была не в отсутствии схем, а в трёх багах `tbl2json.py`/`json2tbl.py`/`lib/parser.py`.**
Они устранены, новых схем писать почти не потребовалось (причина — в разделе 4).

### 3.1. Потеря хвостового пула (`data_dump`)
У **811/844** файлов после объявленных таблиц есть «хвост» (пул строк/массивов, на который ссылаются `toffset`-указатели).
`tbl2json.py` сохранял хвост только при **полном** отсутствии схемы:
```python
if has_extra and not has_schema:   # ← терялся хвост, если схема есть, но header не покрыт
```
Когда header не имел подходящей схемы (hex-режим), хвост отбрасывался → `json2tbl` давал файл короче оригинала;
разница равнялась ровно длине хвоста (например у `t_status`: 398158 → 297792, разница = 100366 = длина хвоста).

**Исправление:** введён флаг `all_headers_covered` — хвост сохраняется, если **хотя бы один** header не покрыт схемой.
Один только этот фикс дал **90.0% → 98.5%**.

### 3.2. Потеря `length` у пустых таблиц (`count == 0`)
5 файлов (`t_mon_d0000`, `t_mon_d0000d`, `t_mon_d0211`, `t_mon_a1001`, `t_npc_c0015`) имеют `count=0` (только заголовок, 88 B).
`tbl2json` удалял `length` из JSON, а `json2tbl` в hex-режиме брал длину из первой записи → писал `length=0`.

**Исправление:** `tbl2json` теперь оставляет `length` в JSON; `json2tbl` не затирает сохранённую длину нулём.
→ эти 5 файлов + `t_btlsys.tbl` стали byte-exact.

### 3.3. Зацикливание на битом `toffset` (`lib/parser.py`)
`readtext` читал по байту до `\0`; при указателе за EOF `stream.read(1)` возвращал `b""` вечно → зависание
(`t_mapjump`, `t_active_voice`, `t_inc`: «TIMEOUT»).
**Исправление:** guard от EOF и лимит длины (`max_length=0x10000`); режим `strict=True` (только для таблиц через
`process_data`) бросает исключение — а `tbl2json` при ошибке декодирования **откатывает header на hex**.
Это одновременно устраняет зависание и, т.к. неверная (размер-совпавшая, но чужая) схема даёт битый указатель,
переводит такие header'ы в байт-точный hex. → `t_mapjump`, `t_active_voice`, `t_achievement` стали byte-exact.
(Дизасм — `readtextoffset` без `strict` — поведение не изменилось.)

### 3.4. O(n²) при дампе хвоста
```python
hex_text = " ".join(remaining.hex()[j:j+2] for j in range(0, len(remaining.hex()), 2))
```
`remaining.hex()` вычислялся **на каждой итерации** генератора. У `t_inc` хвост 629 КБ → квинтиллионы операций
(«зависание» без CPU). **Исправление:** `.hex()` считается один раз → `t_inc` round-trip за 1.7 c, byte-exact.

## 4. Почему новых схем почти не потребовалось
Подбор схем — по **размеру записи** (fallback upstream'а). Если размер совпал и layout совпал, `json2tbl`
пересобирает пул ровно в исходном порядке → byte-exact. Все 842 прошедших таблицы подтверждают совместимость layout.

Два оставшихся файла — случай, когда **размер совпал, а layout — нет** (схемы от другой игры): порядок и состав
пула строк/массивов расходится, `toffset`-указатели уезжают на 1–несколько байт. Это **тот же класс проблемы**,
что остаток Этапа 4 (слоты указателей).
Пример (`t_condition_info`): оригинал пишет в пул пары `[имя][флаг]` подряд без выравнивания
(`炎傷\0\0` + `NZS\0` …), а сгенерированный пул смещён на 1–4 байта из-за иного набора/порядка полей схемы Kai.

Чтобы закрыть эти 2 файла, нужна **собственная Kyoto-схема** для `ConditionInfoTableData`/`CostumeAttachOffset`
(см. `DOCS/How to make a schema.md`): восстановить по 0x-дампу точный список полей и их порядок так, чтобы
порядок записи пула совпал с оригиналом.

## 6. Ограничения / риск
- `t_condition_info` и `t_costume` **не проходят** byte-exact. Для них `json2tbl` даёт файл того же размера, но с
  иными указателями (частично битые строки) → **не пригодны к правке и пересборке** этим инструментарием.
  В пайплайне сборки такие таблицы должны проходить как «hex passthrough» (без изменений) до написания Kyoto-схем.
- Byte-exact round-trip доказывает самосогласованность разобрать↔собрать, но не доказывает, что **семантика полей**
  верна (схема может быть от другой игры при совпадении размера). Для UI-текста это безопасно (строки декодируются
  корректно), но при сомнениях нужна сверка со схемой Kyoto.
