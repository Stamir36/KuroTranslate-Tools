# ЭТАП 6 — Карта перевода

**Статус: ЗАВЕРШЁН.**

## 1. Что сделано
`work/tools/build_translation_map.py` собрал карту перевода из двух источников:
- **Сценарии** — `work/extract/script/**/*.dat`: сканируются UTF-8 «прогоны» байт, из них отбираются строки с японскими
  символами (диапазоны `\u3000-\u30ff`, `\u3400-\u9fff`, `\uff00-\uffef`).
- **Таблицы** — `work/tbl_json/*.json`: рекурсивно собираются строковые значения (уже разобранные схемами),
  hex-дампы (`data`) и служебные поля пропускаются.

Формат записи (по одной строке — один JSON-объект):
```json
{"id":"script\\scena\\00_00_00.dat:0x156d1","file":"script\\scena\\00_00_00.dat",
 "kind":"script","jp_text":"…","ru_text":"","context":"scena/ai/ani/obj @0x156d1"}
```

## 4. Важные наблюдения для переводчика
- **Строки содержат inline-разметку**, которую нельзя терять: `<s40>`, `<C0>`, `<C4>…</C>`, `<R>…</R>`, `<I1016>`,
  `\u3000` (идеографический пробел), `\n`. Пример:
  `<s40><C0>解放可能な能力に <s54><I1016><s40> で<C4>カーソル</C>を合わせ\u3000<s80>\u3000<s40>`
- **Много отладочных/AI-строк** (`M_ADV_CHR_SET:…`, `+--- 回復処理 ---`), самые частые повторы — служебные
  (`正しくない数値を設定しようとしている。` встречается 2080 раз). Их можно либо переводить один раз и применять
  ко всем вхождениям, либо оставлять.
- Часть строк — имена операндов/команд (`通常攻撃１`), т.е. внутриигровые подписи.
- **API-строки сцены** (`<Rソウルアビリティ>…`) — ruby-аннотация (фуригана); при переводе обычно требуется
  сохранять обрамление `<R…>`.

## 5. Ограничения
- Извлечение из `.dat` — **эвристика** (скан UTF-8-прогонов + фильтр по JP-диапазонам). Возможны редкие пропуски
  (кириллица/латиница в японском тексте не мешает — фильтр по наличию японского символа) и редкие ложные
  срабатывания (бинарные данные, декодируемые как UTF-8). Примерный шум: 41 запись длиной ≤1 символ.
- Для двух «hex-таблиц» (`t_condition_info`, `t_costume`, см. Этап 5) строки **не извлечены** — они в hex-дампах.
- `ru_text` пока пустой — заполняется переводчиком.
