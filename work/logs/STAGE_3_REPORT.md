## 3. Причина расхождения FPACker (доказано)
FPACker почти всегда 1:1, но на `table.pac` расходится: он сортирует строки/данные «естественно, но численно», а оригинал — **лексикографически по цифрам**. Пример (порядок пула имён):

- Оригинал: `t_battle_1030`, **`t_battle_10304`**, `t_battle_10305`, `t_battle_10402`…, затем `t_battle_1050`.
- FPACker: `t_battle_1030`, **`t_battle_1050`**, `t_battle_1110`… (5-значные уехали в конец).

Разница задевает только имена с 4- и 5-значными числами (все `t_battle_*`), отсюда ровно 28 записей.

## 4. Выведенный алгоритм укладки (воспроизводит оригинал 100%)
Измерено на всех трёх архивах (`work/logs/agent_log.md`):
- **Записи** (32 байта) отсортированы по полю `crc32(имя)^0xFFFFFFFF` по возрастанию. `padding=0`.
- **Пул имён** и **секции данных** идут в одном и том же порядке «natural sort»:
  - числовые прогоны сравниваются **лексикографически слева-направо** (left-aligned), а не численно;
  - **регистр игнорируется** (ASCII toupper);
  - прочие символы — по коду.
  - Совпадение порядка: пул имён **844/844, 1016/1016, 1148/1148**; данные **844, 1016, 1132/1148** (16 расхождений — это zero-size файлы с общим `doff`, на байты не влияют).
- Данные — вплотную, **без выравнивания/паддинга** (проверено: `gaps=0`, `data_end == filelen`).
- Заголовок: `FPAC` + `u32 n` + `u32 first_file_address (=16+n*32+Σ(len(имя)+1))` + `u32 1`.

## 5. Инструмент
`work/tools/pack_fpac.py`:
```
python pack_fpac.py <directory> <output.pac> [--prefix NAME] [--reference orig.pac]
```
- без `--reference` — восстанавливает порядок по выведенному алгоритму (проверено 1:1 на всех трёх);
- `--reference` — берёт **точный** порядок имён/данных из оригинального pac (гарантия 1:1 даже при аномалиях, например zero-size файлах).
