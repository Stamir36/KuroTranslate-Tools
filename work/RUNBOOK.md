# RUNBOOK — русский перевод KYOTO XANADU -the Blooming Phantom- (PC, JP)

Практическое руководство для переводчика/сборщика. Всё, что создаётся, лежит в `work/`.
**Не трогать (только чтение):** `Файлы для перевода/` (оригинальные `.pac`), `KuroTools-master_ForUPDATE/`, `DOCS/`,
`ColdSteel-TranslationApp/`.

| Путь | Что это |
|---|---|
| `Файлы для перевода/{table,script,scene}.pac` | ОРИГИНАЛЫ (только чтение) |

Скрипты в `KuroTools/` — движок (дизасм/ассембл `.dat`, `tbl2json`/`json2tbl`). Запускать их нужно **из каталога

Окружение: Python 3.10+. Все команды ниже — с `PYTHONUTF8=1` (иначе cp1251-консоль ломает вывод).
```bash
export PYTHONUTF8=1
```

## 1. Кодировка и разметка (правила перевода текста)

- Строки — **UTF-8**. Русский текст можно писать прямо в JSON/`.jsonl` (JSON сохраняется `ensure_ascii=False`).
- **Не удалять встроенную разметку** — это управляющие теги движка. Их надо сохранять в переводе:
  - `<s40>`, `<s80>` — задержки/скорость вывода;
  - `<C0>`, `<C4>…</C>` — цвет/стиль; `<R>…</R>` — руби-фуригана; `<I1016>` — иконка;
  - `\u3000` (идеографический пробел), `\n` — перенос строки;
  - в `.dat`-скриптах — плейсхолдеры вида `%s`, `%d`, `\n`, `\"`.
- **Не менять** идентификаторы/пути/ключи (`M_ADV_CHR_SET:`, `ADV_CHR_POS_AUTO:` — служебные префиксы, их лучше
  оставлять как есть, переводя только «человеческую» часть).
- Порядок и число строк в таблице менять нельзя. Для `.tbl` редактируется только значение строкового поля.

## 2. Таблицы (.tbl) — основной поток

### 2.1 Разобрать оригинал в JSON (уже сделано, но можно повторить)
```bash
cd KuroTools
python tbl2json.py ../work/extract/table/t_item.tbl      # → t_item.json в CWD
```

### 2.2 Перевести
Открыть `work/tbl_json/<t_name>.json`, в полях-строках (`toffset`) заменить японский текст на русский.
Ориентир по объёму — `work/translation_map/tables.jsonl` (21 363 строки; уникальных 18 252).

### 2.3 Собрать обратно и проверить
```bash
cd KuroTools
python json2tbl.py ../work/tbl_json/t_item.json          # → t_item.tbl в CWD
```
**Проверка (обязательна):** собрать таблицу из *непереведённого* JSON и сравнить с оригиналом —
если совпало байт-в-байт, инструментарий корректен для этого файла.
Полный прогон: `python work/tools/batch_tbl.py work/extract/table` (см. `work/logs/batch_tbl_result.txt`).

### 2.4 Известные исключения
- `t_condition_info.tbl`, `t_costume.tbl` — **НЕ редактировать** этим инструментарием: round-trip не байт-в-байт
  (нет корректной Kyoto-схемы). Собирать «как есть» (hex passthrough) либо сначала написать схему
  (`KuroTools/schemas/headers/{ConditionInfoTableData,CostumeAttachOffset}.json`, см. `DOCS/How to make a schema.md`).

## 3. Сценарии (.dat) — диалоги и квесты

В форке уже есть готовый поток: `.dat` → `.py` → правка → `.dat`.

### 3.1 Разобрать
```bash
cd KuroTools
python dat2py_batch.py -i ../work/extract/script/scena        # .py появятся в KuroTools/data_to_py/
```
(для 756 сценариев `scena/`; для других подпапок — `ai/`, `ani/`, `obj/`).
Каждый файл — Python-скрипт, текст строк в литералах; **строки можно менять, логику — нет**.

### 3.2 Перевести
Есть два способа:
- **A. Правка `.py` напрямую** — заменить строковые литералы на русские (сохраняя разметку из §1).
- **B. Карта строк** `KuroTools/strings_map.json` вида `{"японская строка": "русская строка"}` —
  тогда `py2dat_batch.py` сам подставит переводы во все файлы (рекомендуется для повторяющихся строк).

### 3.3 Собрать обратно и проверить
```bash
cd KuroTools
python py2dat_batch.py --only-translated true     # .dat появятся в KuroTools/py_to_data/
```
Проверка одного файла: `python work/tools/roundtrip_dat.py work/extract/script/scena/00_00_00.dat <scratch>`
(использует `--markers True` — иначе теряются маркеры строк).

> **ВАЖНО (ограничение Этапа 4):** для `.dat` round-trip **не** байт-в-байт: 4-байтные слоты указателей на
> строки (`varout`/struct-параметры) могут располагаться иначе при равных строках. Файл получается того же
> размера и функционально корректный, но перед выпуском **тестировать в игре**. Размер и секции кода/строк
> восстанавливаются точно.

## 4. Пересборка архивов (.pac)

```bash
# пересобрать все три архива из work/extract и проверить байт-в-байт с оригиналами
python work/tools/build_pacs.py --src work/extract --out work/build/pac \
       --orig "Файлы для перевода" --verify

# только таблицы
python work/tools/build_pacs.py --only table --verify
```
Результат: `work/build/pac/{table,script,scene}.pac`. На неизменённых данных — **все три EXACT** (проверено).

Примечания:
- Пакер `work/tools/pack_fpac.py` сортирует записи по `crc32(имя)^0xFFFFFFFF` и воспроизводит «natural sort»
  оригиналов (числовые прогоны — лексикографически, регистр не важен). `--reference` берёт точный порядок из
  оригинала, поэтому пересборка безопасна.
- **FPACker.exe `pack` не годится для `table.pac`** (28/844 записей расходятся) — использовать только `pack_fpac.py`.

## 5. Установка в игру
1. Сделать бэкап оригинальных `table.pac`, `script.pac` (и `scene.pac`, если трогали).
2. Скопировать собранные `work/build/pac/*.pac` в каталог игры вместо оригиналов.
3. Запустить игру, проверить меню/диалоги/статусы.
> Вопрос «читает ли игра loose-файлы поверх `.pac`» **не подтверждён** — надёжный путь — подмена `.pac`.
> `scene.pac` — это НЕ диалоги (576 `.bin` + 572 `.json`, ассеты сцен); трогать в последнюю очередь и только
> после явного решения.

## 7. Если что-то сломалось
- `tbl2json`/`json2tbl` запускать **из `KuroTools/`** (иначе не найдёт `schemas/`).
- «unterminated string» / «failed to decode header … using raw hex» — нормальный откат на hex (схема не подошла).
- Пустой/битый `.py` от `dat2py` → см. `KuroTools/LogDisassembler.txt`.
- Бэкапы правок движка: `work/backup/`.
