# KuroTranslate Tools — рабочий цикл через launcher

Запуск: `python launcher.pyw` (или двойной клик по `launcher.pyw`).
Прямо в окне — кнопки для **PAC**, **TBL** и **DAT**. Ниже — пошаговый цикл.

Проверено на `table.pac`: цепочка **unpack → tbl2json -g Kyoto → json2tbl → pack**
даёт архив, **байт-в-байт идентичный оригиналу** (844/844 таблиц, 0 ошибок).
Распаковка/упаковка сами по себе тоже байт-точные для всех трёх архивов.

## 0. PAC архивы (FPAC)
Кнопки в разделе **«PAC архивы (FPAC)»**:
* **Распаковать .pac** — выбираешь `.pac`; файлы раскладываются в
  `pac_unpacked/<имя>/…` с сохранением внутренних путей
  (`table/…`, `script/scena/…`, `scene/…`).
* **Собрать .pac** — выбираешь папку (напр. `pac_unpacked/table` или `json_to_tbl`);
  архив кладётся в `pac_packed/<префикс>.pac`. Префикс имён внутри архива
  (`table/script/scene`) берётся из имени папки; если имя другое — спросит.
* **Информация об архиве** — число файлов/размер.

> Байт-точность сохраняется, только если префикс совпадает (table/script/scene)
> и состав файлов не менялся.

## 1. TBL (таблицы)
Раздел **«Пакетная работа с TBL файлами»**:
1. **Разобрать .tbl** — выбираешь папку с `.tbl` (напр. `pac_unpacked/table`);
   JSON-ы складываются в `tbl_to_json/`.
   Перед запуском выбери **Игра (схема)** (по умолчанию `Kyoto`; `Авто` — подбор по размеру).
2. **Собрать .json в .tbl** — `tbl_to_json/` → `json_to_tbl/`.
3. **Парсинг TBL строк JSON в XLIFF** — извлечь строки в `tbl_strings.xliff` и обратно.
4. **Строки → TSV (для ИИ)** — экспорт всех переводимых строк в `strings.tsv`
   (колонки: `id  source  translation`). Удобно целиком отдать чатовому ИИ.
5. **Перевод TSV → строки** — после того как заполнил 3-ю колонку, импортирует
   перевод обратно в JSON в `tbl_to_json/` (по значению строки).
6. **Запустить XLIFF редактор** — встроенный GUI-редактор.

## 2. DAT (скрипты)
Раздел **«Работа с DAT файлами»** — 5 шагов:
1. Дизассемблировать DAT (`dat2py_batch.py`) — выбираешь папку с `.dat`.
2. Извлечь строки (`py_to_xliff.py`) → `data_game_strings.xliff`.
3. Редактировать перевод (XLIFF).
4. Создать карту перевода (`inject_translations.py`).
5. Скомпилировать DAT (`py2dat_batch.py`).

Важные особенности (уже встроены):
* **Извлекаются ВСЕ строки**, а не только `PUSHSTRING`: имена/ошибки в
  struct-параметрах, строки `CallFunctionFromAnotherScript`, входные/выходные
  переменные и т.п. — извлечение симметрично замене при компиляции.
* **Английский текст тоже извлекается** (любая фраза с пробелом/переводом
  строки; одиночные идентификаторы вида `chr001`, `item_name_01`, `Loc_187`
  отсеиваются автоматически).
* При дизассемблировании **сохраняются маркеры строк** (`ADDLINEMARKER`).
* Корректность round-trip проверяется **семантически**: `disasm(orig) ==
  disasm(rebuild(orig))`. Совпадение текста означает, что восстановлен ровно
  тот же код/операнды/строки. Побайтовое совпадение `.dat` недостижимо: Falcom
  раскладывает одинаковые/пустые строки по разным ячейкам, и адреса ячеек не
  выводятся из дизассемблированного представления (это безвредно — указатели
  пересчитываются). Поэтому размер может отличаться на доли процента.
* Исправлены две реальные ошибки кодирования/декодирования, которые давали
  неверные данные в пересобранных `.dat` (и привели бы к багам/вылетам игры):
  * `PUSHFLOAT` дважды кодировал число — `FLOAT()` был не идемпотентен, и,
    например, `0.0` превращалось в `2147483648.0`, `1.0` — в `2413821952.0`;
  * адрес возврата `PUSHRETURNADDRESSFROMANOTHERSCRIPT` в части скриптов
    записывался как неверный (`start_code_section - 1`), потому что метка
    ссылки и метка определения расходились (`Loc_120` против `Loc_15`).

## 3. Полная сборка (пример)
```
1) Распаковать .pac            (table.pac → pac_unpacked/table)
2) Разобрать .tbl              (pac_unpacked/table → tbl_to_json, игра = Kyoto)
3) Строки → TSV (для ИИ)       → strings.tsv
4) перевести strings.tsv
5) Перевод TSV → строки        (применить перевод)
6) Собрать .json в .tbl        (tbl_to_json → json_to_tbl)
7) Собрать .pac                (json_to_tbl, префикс = table → pac_packed/table.pac)
```

## 4. Автопроверки (selftest.py)
Без интерактива; код возврата `0`, только если все проверки прошли.
```
python selftest.py --tbl <каталог .tbl> --game Kyoto   # байт-в-байт
python selftest.py --pac <file.pac>                    # байт-в-байт
python selftest.py --dat <каталог .dat> [--limit N]    # семантическая проверка кода
python selftest.py --tbl <dir> --dat <dir> --pac <f>   # всё сразу
```
Пример запуска «всё сразу»:
```
python selftest.py --tbl ../work/extract/table --pac "../Файлы для перевода/table.pac" --dat ../work/extract/script/scena --limit 100
```
Ожидаемый результат: TBL `exact%=100.0`, PAC `identical=True`,
DAT `semantic_ok = total` (при `code_diff=0 err=0`).

Проверенные значения на полном наборе Kyoto:
* TBL: `total=844 ok=844 diff=0 err=0 exact%=100.0`;
* DAT: `obj 13/13`, `ai 132/132`, `ani 115/115`, `scena 756/756` — `semantic_ok`
  (часть файлов совпадает и побайтово; остальные различия — только раскладка
  строкового пула);
* PAC: `table.pac identical=True`.

## Конвейер перевода (карты jsonl) — основной рабочий процесс

Панель лаунчера — три вкладки: **Перевод** (рабочий порядок, перевод чатом,
альтернатива XLIFF), **Сборка** (одна кнопка «Собрать всё», пошаговые шаги,
автотест) и **Ещё** (старые инструменты: DAT, TBL, PAC, строки↔TSV). Внизу
всегда видны язык, `Прервать` и подпись.

Кнопки блокируются только на время операции и **включаются обратно** после её
окончания; гаснут насовсем только те, чей скрипт или нужный файл отсутствует
(`tools/test_launcher_state.py` без кликов проверяет и это, и то, какую команду
запускает каждая кнопка).

Во вкладке «Перевод» сверху выпадающий список «Что переводим:» —
`Таблицы .tbl (UI, меню)` или `Скрипты .dat (диалоги)`. Он задаёт карту для
всех кнопок вкладки.

### Основной путь — редактор карты

1. `1. Разобрать игру (.dat + .tbl)` — распаковка `.pac`, `.tbl → .json`,
   `.dat → .py`, сборка обеих карт. Идемпотентно: готовое не переделывается,
   а повторная сборка карты **не теряет перевод** (см. ниже).
2. `2. Открыть редактор карты` — [map_editor_gui.py](map_editor_gui.py).
3. Вкладка «Сборка» → **`★ Собрать всё → pac_packed`** (главная кнопка).
   Одна кнопка делает весь путь: переносит карту в файлы (`apply`) → собирает
   `.tbl`/`.dat` → упаковывает и сверяет с оригиналом. Результат всегда
   `pac_packed/<архив>.pac`, в логе — строка `ИТОГ:` с путём, размером и
   списком отличий. Какой архив собирать, задаёт список **«Что собирать»**
   (`table`, `script`, `scene`). `Собрать всё начисто (--force)` пересобирает
   всё, не глядя на даты.
4. Пошаговый вариант, если нужно что-то одно: `3. Применить перевод в файлы`
   → `5а/5б. Собрать только .dat/.tbl` → `6. Упаковать .pac` (спросит архив).
   Шаг сборки пересобирает `.tbl` только когда `.json` действительно новее,
   поэтому «844 таблицы, собрано 0» больше не появляется (с `--force` — всё).
5. `SELFTEST (автотест)` — проверяет побайтовую распаковку→упаковку архива
   (`pac_packed/<архив>.pac`, а если его ещё нет — оригинал):
   ожидаемый результат `identical=True`, код возврата 0.

### Редактор карты (`map_editor_gui.py`)

Окно делится на три части: **страница карты** (слева), **блок для ИИ** и
**поле ответа** (справа), навигация — снизу.

* Фильтры сверху: карта, файл (`table/t_text.tbl` …), «непереведённые /
  переведённые / все», «только с `%s`/тегами», поиск по японскому и русскому.
* `Скопировать блок` — текущая страница (по умолчанию 50 строк) уезжает в
  буфер как jsonl. Этот же текст перед вами в поле «1. Скопируйте этот блок».
* Ответ ИИ вставить в поле «2. Вставьте ответ ИИ» и нажать **`Применить блок`**
  (или `Ctrl+Enter`). Принимается jsonl, JSON-массив, `{"id": "перевод"}`,
  `id<TAB>перевод` — и всё это даже внутри ```-ограждения.
* Применённые строки **сохраняются в карту сразу** и исчезают из выдачи,
  страница сама наполняется следующими — проход идёт до конца без разметки.
* Галочка **«не применять строки, где потеряны `%s`/теги»** (включена)
  отбрасывает опасные правки: если в переводе пропал `%s`/`%d`, тег `<C1>`
  или перенос строки — строка не записывается, а причина пишется под кнопкой.
* `Перевести вручную` переносит блок в поле ответа — можно заполнять `ru_text`
  самому; поля `RU` под каждой строкой тоже работают (`Ctrl+S` — сохранить).
* `Пересобрать карту заново` — повторный `translation_workflow.py maps`
  (готовый перевод не теряется).

### Второй путь — куски для ИИ без редактора

`Куски для ИИ (по 500 строк)` → `chunks/part_0001.jsonl` … отдать ИИ →
`Импорт кусков из чата`.

### Третий путь — XLIFF

`Карта → XLIFF` → `Редактор XLIFF` → `XLIFF → карта`.

Ручной запуск того же (из каталога `KuroTools`):

```
python translation_workflow.py prepare
python map_editor_gui.py --kind tbl
python translation_workflow.py map2xliff --kind tbl
python translation_workflow.py chunks --kind script --size 500 --only-empty
python translation_workflow.py xliff2map --kind tbl
python translation_workflow.py apply --kind tbl
python translation_workflow.py build --what table          # пересобирает только устаревшее
python translation_workflow.py build --what table --force  # пересобрать всё
python translation_workflow.py pack  --what table          # префикс table/ ставится сам
python translation_workflow.py all   --what table          # всё вместе + сверка с оригиналом
python translation_workflow.py status
```

Кнопка «Собрать всё» и `all` — это одна и та же цепочка; после упаковки
печатается `ИТОГ:` и код возврата `1`, если что-то не сошлось с оригиналом.

Формат записи карты:

```json
{"id": "table/t_text.tbl:2442", "file": "table/t_text.tbl", "kind": "tbl",
 "jp_text": "Steamオーバーレイでポーズ", "ru_text": "", "context": "tbl string field"}
```

`id` — файл плюс индекс строки, `ru_text` заполняет переводчик (пусто = не
переведено). Карта не содержит имён функций, идентификаторов и служебных
строк: фильтр `is_text()` отсеивает `AniReset`, `item_name_01`, `chr001`,
`Loc_187`, `sound.StopEnvSe`, шестнадцатеричный дамп, но при этом **берёт**
японский текст любой длины и английский текст (фразы вида `Press any key to
continue`, одиночные слова вида `Continue`).

Раскладка каталогов (всё внутри `KuroTools/`):

| каталог | что внутри |
|---|---|
| `pac_unpacked/<архив>/<архив>/` | распакованные оригиналы |
| `tbl_to_json/` | `.json` после `tbl2json` (уже со схемами) |
| `data_to_py/` | `.py` после `dat2py`) |
| `translation_map/` | `scripts.jsonl`, `tables.jsonl`, `MAP_INDEX.csv` |
| `xliff/` | `script.xliff`, `tbl.xliff` |
| `chunks/` | куски jsonl для ИИ |
| `json_to_tbl/`, `py_to_data/` | собранные `.tbl` / `.dat` |
| `pac_packed/` | готовые архивы |
| `translation_map/*.jsonl.bak` | копия карты перед последней пересборкой |
| `selftest_work/` | рабочий каталог автотеста (можно удалять) |

Проверенные значения на полном наборе Kyoto:

* карты: `scripts=68876` записей, `tables=33999` записей;
* таблицы: 844 разобрано; 656 дают текст (658 раскодированы схемами, часть
  отдаёт текст из `tail_strings`); остальные — числовая настройка без строк
  (`t_battle_*`, `t_ani_param`), при сборке восстанавливается байт-в-байт;
* сборка таблиц: 843 из 844 совпадают с оригиналом **побайтово**, отличается
  только та, где есть перевод;
* скрипты: 1016 из 1016 `.dat` пересобираются, код совпадает при повторной
  дизассемблировании (см. `selftest.py --dat`).

### Что попадает в карту, а что нет

Правила отбора (`is_text()` в `translation_workflow.py`) — они же защищают от
того, чтобы игра сломалась из-за переведённого идентификатора:

| берём | отсеиваем |
|---|---|
| японский текст любой длины (кана, кандзи, полноширинная пунктуация) | hex-дампы байтов (`8F CB 01 00 …`) — это содержимое бинарных таблиц |
| английские фразы (`Press any key to continue`, `Sound Error: file not found`) | идентификаторы и имена: `Kyoto`, `Head`, `hold`, `AniReset`, `chr001`, `item_name_01`, `v00_s0039` |
| английские слова с заглавной буквы в таблицах (`Continue`, `Cast`, `Name`) | служебные ключи таблиц: `npc`, `system`, `worldmap`, `entry`, `white` |
| ссылки в фигурных скобках только если рядом есть японский текст | ссылки на другую таблицу без текста: `<TXT TXT_YES>` |
| | технические подписи: `vol.10 A3`, `01 00`, `◆◆◆`, `………………` |

Дополнительно:

* **`t_voice` не попадает в карту** — таблица голосовых ресурсов, её данные
  это имена файлов (`v00_s0039`), а не текст локализации (`SKIP_TABLES` в
  `translation_workflow.py`).
* **Текст таблиц без схемы берётся из `tail_strings`** (пула строк после
  объявленных таблиц). Например `t_action_card` отдаёт 55 настоящих японских
  описаний. Раньше было наоборот: брались hex-структуры из `data`, а пул строк
  терялся — из-за этого 74% карты таблиц было мусором.
* **Ключ в строке `KEY：текст` не переводится.** Такие строки (для Kyoto их
  2152) кладутся в карту только видимой частью, ключ хранится в поле
  `key_prefix`, и при обратной записи возвращается дословно.
* **Поле `flags`** подсказывает переводчику/ИИ, что менять нельзя:
  `format` (`%s`/`%d`), `markup` (теги `<...>`), `newline` (перенос строки),
  `whitespace`, `short`, `suspect`.
* **Повторный `prepare`/`maps` не теряет перевод.** Готовые `ru_text`
  переносятся из прежней карты, в том числе если источник уже переведён
  (тогда японский оригинал восстанавливается из прежней карты). Дополнительно
  строка возвращается **по номеру слота**: «Применить перевод» подставляет
  русский прямо в `.json`/`.py`, а фильтр `is_text()` перевод с тегами и
  цифрами текстом не считает — такая строка раньше исчезала из карты вместе с
  переводом. Если в том же слоте прежняя карта хранит ровно этот перевод, он
  возвращается вместе с японским оригиналом.
* **Перед перезаписью карты делается копия** `translation_map/<карта>.jsonl.bak`,
  а в конце печатается отчёт: `потеряно: scripts=0 tables=0`. Если число
  переводов всё же уменьшилось, в логе будет `ВНИМАНИЕ: N переводов не
  перенесены` и путь к копии. Если каталогов `tbl_to_json`/`data_to_py` нет,
  карта не перезаписывается пустой, а остаётся прежней.
* Строки в карте сопоставляются по полному японскому тексту, а не по индексу:

## Перевод одной сцены (диалоги событий)

Диалоги событий лежат **не в `.dat`**, а в таблицах `t_evmes_<сцена>.tbl`
(например `t_evmes_00_00_01.tbl` — пролог сцены `script/scena/00_00_01.dat`).
Сам `.dat` — это только постановка (кто вышел, какая анимация, какая озвучка);
переводить в нём нечего, его 61 строка — служебные сообщения движка.

1. **Найти сцену по строке диалога:** `python tools/find_text.py "おんどれ、ちょこまかしくさって"`.
   Инструмент ищет фрагмент побайтово по всему репозиторию, сам определяет, к
   какой карте относится файл, и печатает сцену целиком (все реплики по порядку).
   Одна сцена может лежать сразу в двух местах — например `00_00_00`: реплики
   погони в `table/t_evmes_00_00_00.tbl`, а дисклеймер о вымысле в
   `script/00_00_00.dat` — переводить надо оба, поэтому в файле сцены есть
   разделы для обеих карт.
2. **Посмотреть все строки файла:** `python tools/scene_show.py table/t_evmes_00_00_01.tbl`.
   Номер слева — номер слота в карте, именно он попадает в `id`.
3. **Перевести** и сохранить как `tools/scene_ru/<сцена>.json` (пример —
   `tools/scene_ru/00_00_01.json`, там же пояснение кто говорит и почему).
4. **Внести в карту:** `python tools/scene_set.py 00_00_00` — каждая строка сверяется
   с японским текстом по своему слоту, при расхождении ничего не пишется.
   Табличные слоты уезжают в `translation_map/tables.jsonl`, скриптовые — в
   `scripts.jsonl`, копия каждой карты сохраняется рядом (`.bak_ЧЧММСС`).
5. **Собрать:** `python translation_workflow.py all --what table` и, если
   правились скрипты, `python translation_workflow.py all --what script`
   (или кнопка «Собрать всё» в лаунчере с выбором архива).
6. **Проверить внутри архива:** `python tools/scene_verify.py 00_00_00` — перевод на
   месте, id сообщений и ссылки на озвучку целы, `.tbl` собирается обратно
   байт-в-байт, `.dat` разбирается обратно и `selftest` подтверждает, что код
   сцены не пострадал.

Особенности, которые стоит знать:

* **Подпись говорящего** (`text3`) — это переопределение имени. Пустая подпись
  означает «взять настоящее имя персонажа», поэтому имя героя правится в
  `t_chr_name.tbl` (для Рэя это слоты 50–54: `レイ` → `Рэй`,
  `神矢 伶` → `Рэй Камия`).
* **Теги вида `<w250>`** (пауза), `%s`, перенос строки `\n` переносятся в
  перевод дословно — карта хранит их в полях `flags` и предупреждает о потере.
* **Озвучка не меняется**: `text2` (`Mes_ADV`/`Mes_MAYA`) — это ссылка на
  голосовой банк, её трогать нельзя, иначе реплика потеряет голос.
* **Скрипты собираются по одному**: `all --what script` компилирует только те
  `.dat`, для которых есть перевод (`py2dat` строчкой в логе), а все остальные
  файлы кладёт в архив **из распакованных оригиналов** — побайтово, как в игре.
  Поэтому в `pac_packed/script.pac` меняются ровно переведённые сцены
  (для пролога: `1015` файлов совпали, отличается `1`), а не все 1016.
  Пересобрать всё сразу можно `build --what script --force`.
* **Служебные строки не трогаем**: `地名演出` (тип подписи места) и
  `カット1 京都街並み` (раскадровка: `PUSHSTRING` сразу с `POP2`, в игре не
  показывается) — это директивы/черновики движка, а не текст для игрока.

### Две ловушки классификатора (исправлены 08.10.2026)

Оба раза страдал один и тот же сценарий: `scene_dump --list` показывал
«осталось мало», а в игре оставались непереведённые реплики. Обе причины
устранены, но знать их надо при любой новой волне.

1. **Полноширинная пунктуация.** `SCRIPT_FULL` ловил весь диапазон
   U+FF01…U+FF5E, а туда попадают «！», «？» и «：». Волна 1 из-за этого
   пропустила ~1 500 настоящих реплик («助けてくださってありがとうございます……！»,
   «一層力が涌いてくるくらいですから！») и все вопросы в выборах. Теперь
   `SCRIPT_FULL` берёт только полноширинную латиницу и цифры
   (`ＡＤＶキャラ設置`, `５００円`).
2. **Правило «встречается в 5+ файлах».** Оно отсеивает библиотечные
   сообщения движка, но вместе с ними потеряло кнопку меню `いいえ` (33 строки)
   и табличку говорящего `女子生徒` (32 строки, парная `男子生徒` была
   переведена как «Ученик»). Обе добавлены вручную.

Аудит остатка — то, что не надо переводить, но полезно перепроверить:

```

движка (`M_*:`, `…に失敗`, `作成。`, `存在しない選択肢`), раскадровка

### Где живёт рабочий мусор

Всё промежуточное — черновики, заготовки сцен, логи — лежит только в
`tools/` и внесено в `.gitignore` файловыми масками (`tools/drafts/*.json`,
`tools/drafts/**/*.json`, `tools/scene_ru/*.json`, `tools/_*.log`,
`tools/_*.txt`, `tools/_wave*/`). В публичный репозиторий из `tools/`
попадают ровно 10 скриптов и два .md — проверить можно так:

```
git ls-files --others --exclude-standard KuroTools/tools
```

**Важно про маски:** файл, попавший под `.gitignore`, перестаёт быть виден
поисковым инструментам (`read_files`, `glob`). Поэтому помощники берут
японский текст прямо из `translation_map/tables.jsonl` — строки нужного
`file` с пустым `ru_text` — а не из черновиков:

```
python tools/find_text.py <сцена>      # показать всю сцену с японским и переводом
```

### Как проводится волна перевода скриптов

Волна — это пачка одинаковых по размеру корзин, по одной на ИИ-воркера.
Рабочий каталог волны (`tools/_wN/`) **не** попадает под `tools/_wave*/` и
поэтому виден и git’у, и воркерам — так воркеры могут читать свои `in/wNN.json`.
После применения перевода и проверок каталог волны архивируется в
`tools/drafts/_applied/wN_scripts/` (вход, выход, `merged.json`, merge-скрипты,
лог сборки) и удаляется из `tools/` — `tools/drafts/_applied/` целиком внесён
в `.gitignore`. Волна 1 лежит там как `w1_scripts` (все `Talk_*` и `00_00_00`),
волна 2 — как `w2_scripts` (выборы, `EVS_*`, `sys_*`, `d*` и остаток реплик).
Волна 2 шла в три захода: `in/in2` — то, что показал классификатор, `in3` —
то, что он срезал (см. «Две ловушки классификатора»).

Порядок волны:

1. `scene_dump.py --kind script --list` — сколько осталось; из карты берём
   японские строки нужных `.dat` вместе с контекстом (соседние реплики),
   чтобы воркер видел сцену, а не отдельную фразу;
2. раскладываем на корзины по ~350 строк и отдаём по одной ИИ-воркеру;
   формат ответа — `{"worker":"wNN","items":[…],"pairs":{японский: русский}}`;
3. проверка (`validate.py`): полнота (все ключи корзины закрыты), неизвестные
   ключи, конфликты между корзинами (побеждает та, чей ключ в её входе),
   затем `lintdict.py` — потерянные `<R>`, непереведённые чтения, парность `«»`;
4. `merge.py` — единый словарь с нормализацией терминов (NORM), исправлением
   опечаток в японском (TYPOS), добором `MISSING` и правками `OVERRIDES`;
5. `apply_ru.py --dict --kind script` → `qa_ru.py --map script` →
   `translation_workflow.py maps` → `test_launcher_state.py` →
   `translation_workflow.py all --what script`.

## Ревью и правка готового перевода (с 08.10.2026)

Перевод закончен: без перевода остались только внутренние строки движка и
заметки разработчика (см. `work/reports/REVIEW_2026-10-08.md`). Дальше — ревью
качества. Оно идёт не «по волнам перевода», а **правками по номерам строк**,
и у этого есть жёсткий безопасный конвейер:

```
черновик (fix_terms.py или ответ воркера)   →  validate_draft.py
    →  *.ok.json  →  apply_ru.py --skip-unknown --no-scene-file
    →  propagate_draft.py (разнести по копиям)  →  validate_draft.py  →  apply
    →  translation_workflow.py all --what script
    →  tools/qa_ru.py --map script  +  tools/check_markup.py
```

Формат черновика — по номеру строки, с двумя защитами (японский текст и
прежнее значение перевода):

```json
{"scene": "w01", "files": {"script/sys_basemenu.dat": {
  "1078": {"jp": "レイは『<C3>", "was": "Рэй прочитал «<C3>", "ru": "…"}}}}
```

* `validate_draft.py` — **единственный** шлюз к карте: сверяет слот, `jp`,
  `was` и запрещает правку, которая теряет тег, меняет число `\n`/`\u3000`/
  `%s` или добавляет полноширинные буквы.
* `apply_ru.py` в режиме по номерам строк сам делает копию карты
  (`*.bak_ЧЧММСС`) и сообщает, если один слот пришёл из двух черновиков с
  разным переводом.
* `propagate_draft.py` нужен потому, что одна реплика лежит десятками копий:
  без разноса одна и та же фраза остаётся переведённой по-разному.
* Карту можно править только через этот конвейер. `maps` и `prepare`
  перезаписывают карты целиком и на время ручной вычитки закрыты `EDIT_LOCK`.

### Кормить воркеров надо нарезкой

`translation_map/scripts.jsonl` — 16 МБ, и агенты-читатели его **не
открывают** (лимит 10 МБ), а `tools/drafts/**` скрыт `.gitignore`, из-за чего
они не могут перечитать свой же черновик. Поэтому перед волной:

```bash
python tools/slice_dump.py --kind script --file Talk_c0000 --chunk 400 \
    --out tools/drafts/rv/src
```

и раздаём воркерам готовые `Talk_c0000.dat.01.json` (≈400 строк, 25 КБ) —
тогда ревью идёт прозой, а не поиском.
